## 3. 설계 결정

### 3.1 구현 옵션: **Option A (subprocess E2E)**

| 옵션 | 내용 | 채택 |
|------|------|------|
| **A** | `SHealthBMI` 실행 파일 subprocess → stdout 캡처 → golden 비교 | ✅ |
| B | `SHealthReporter` 등 출력 로직 추출 후 문자열 단위 테스트 | — |

**선택 근거**

- 프로덕션 BMI·통계 로직을 건드리지 않고 **실제 CLI 경로**를 검증한다.
- 리팩토링 범위가 테스트 인프라에 한정되어 **7~9차 기준선과 충돌이 적다**.
- `shealth.dat` 실데이터 E2E가 QA 목적(TC-25)과 정확히 일치한다.

### 3.2 부동소수·플랫폼 안정화

| 수단 | 적용 |
|------|------|
| **(A) 출력 포맷 고정** | `SHealthBMI.cpp` 연령대·전체 비율 `%f` → `%.2f` |
| **(B) 비교 전 정규화** | CRLF→LF, 끝 공백 제거 (`normalizeOutput`) |
| (C) JSON 구조화 비교 | 미적용 (출력 리팩토링 불필요) |

MSVC/GCC 간 `%f` 기본 자릿수 차이를 제거해 **Windows·Linux CI 매트릭스**에서 동일 golden을 공유한다.

### 3.3 Normal BMI ID 미리보기

프로덕션 동작 그대로 golden에 반영한다.

- `count = 654` (전체 정상 BMI 사용자 수)
- 상위 **10건** `id` 미리보기 + `... (644 more)` 요약
- 전체 ID 목록은 golden에 **포함하지 않음**

## 4. 테스트 디렉터리 통합

### 4.1 Before → After

```
[Before]
src/test/cpp/          ← SHealthBMITest.cpp, GoldenMasterTest.cpp
test/golden/           ← golden baseline

[After]
test/
  cpp/                 ← 단위 + 골든 테스트 소스
  golden/              ← baseline + actual
```

`src/test/` 는 제거하였고, CMake·문서·README의 경로를 `test/cpp/` 기준으로 일괄 수정했다.

### 4.2 ctest 등록 방식 변경

| 항목 | 이전 (`gtest_discover_tests`) | 이후 (`add_test`) |
|------|------------------------------|-------------------|
| ctest 항목 수 | 37개 (테스트별 개별 등록) | **1개** (`SHealthBMITest`) |
| GTest 실행 건수 | 37 | **37** (동일) |
| 생성 파일 | `cmake_test_discovery_*.json`, `*_tests.cmake` | **없음** |
| 장점 | ctest에서 테스트별 필터·실패 위치 | 설정 단순·산출물 없음 |
| 단점 | configure/build 시 discovery 파일 생성 | `ctest -R` 개별 TC 필터 불가 |

Golden만 실행할 때는 ctest 필터 대신 다음을 사용한다.

```bash
cmake --build build --target update-golden
# 또는
SHealthBMITest --gtest_filter=GoldenMasterTest.ShealthDatReportMatchesExpected
```

`.gitignore`에 `cmake_test_discovery*.json`, `*_tests.cmake`를 추가해 재발생 시 커밋되지 않도록 했다.

## 12. 회고 (10차)

### 12.1 달성

- **6차 계획 P2의 핵심(TC-25)** 을 마무리해, 실데이터 기준 **E2E 회귀 안전망**을 확보했다.
- 테스트 자산을 **`test/` 단일 트리**로 정리해 구조 혼란(`src/test` vs `test/golden`)을 제거했다.
- **CI 매트릭스**로 Windows/Linux 간 출력·통계 drift를 조기에 감지할 수 있다.

### 12.2 설계·QA 원칙 (검증됨)

- **의도적 변경과 버그를 분리** — golden 갱신은 명시적 플래그·타깃으로만 허용.
- **최소 프로덕션 침습** — Option A + `%.2f`만으로 교차 플랫폼 안정화.
- **실패 시 진단 용이** — `test/golden/actual/`에 actual 저장 + CI 아티팩트.

### 12.3 한계

- ctest는 **1항목**으로만 보고되며, 개별 TC 필터는 GTest `--gtest_filter`에 의존한다.
- golden은 **`shealth.dat` 내용에 종속** — 데이터 교체 시 반드시 baseline 재검토가 필요하다.
- **커버리지(G3)** 는 여전히 미측정이다.
