```
[P] 당신은 레거시 C++ 코드 QA/리팩토링을 돕는 시니어 C++ 엔지니어입니다.
    SRP, 테스트 주도 리팩토링, 도메인 경계값 정확성에 특히 엄격합니다.

[C] SHealth BMI(C++17) 프로젝트에서 Cursor AI가 항상 따라야 하는 규칙을
    프로젝트 루트의 `.cursorrules`로 작성하려고 합니다.

    ## 프로젝트 개요
    - 목적: CSV(id, age, weight, height)에서 BMI를 계산하고,
      연령대(20~70, 10년 단위)별·전체 저체중/정상/과체중/비만 비율을 산출
    - BMI 공식: weight(kg) / (height(m))²
    - 분류 기준 (경계값 포함, 한 곳에서만 정의):
      · ≤18.5  → 저체중 (Underweight)
      · 18.5 초과 ~ 23 미만 → 정상 (Normal)
      · 23 이상 ~ 25 미만 → 과체중 (Overweight)
      · 25 이상 → 비만 (Obesity)  ← BMI=25.0 반드시 비만
    - 결측 보정: weight=0 또는 height=0 → 같은 연령대(10년 단위) 평균으로 대체
    - height≤0 또는 bmi≤0 → 통계 집계에서 제외 (0으로 나누기 금지)

    ## 기술 스택
    - C++17, CMake 3.10+, Google Test v1.14 (FetchContent 자동 다운로드)
    - 빌드: `mkdir build && cd build && cmake .. && cmake --build .`
    - 테스트: `cd build && ctest --output-on-failure`
    - 실행: 프로젝트 루트에서 `.\build\Debug\SHealthBMI.exe` (shealth.dat 필요)

    ## 현재 아키텍처 (3차 리팩토링 완료, SRP 분리)
    | 클래스/모듈      | 책임 |
    |-----------------|------|
    | `BmiTypes`      | `HealthRecord`, `BmiCategory`, 상수 namespace |
    | `CsvReader`     | CSV 로드·파싱·행 검증 |
    | `BmiCalculator` | BMI 계산·분류 |
    | `DataImputer`   | 연령대별 weight/height 0 보정 |
    | `BmiStatistics` | 연령대/전체 비율, 정상 BMI 사용자 ID |
    | `SHealth`       | 파사드 — `processFile`에서 위 컴포넌트 조율 |
    | `SHealthBMI.cpp`| main, 콘솔 출력 |

    ## 디렉터리 구조
    ```
    CMakeLists.txt
    shealth.dat
    src/main/cpp/   ← 라이브러리(shealth_lib) 소스
    src/test/cpp/   ← SHealthBMITest.cpp
    Report/         ← 리팩토링 보고서 (참고용)
    ```

    ## 상수·네이밍 규칙 (이미 도입됨, 변경 시 일관 유지)
    - BMI 임계값: `BmiThresholds::kUnderweightMax` 등
    - 연령대: `AgeDecade::kMin/kMax/kStep`
    - 레거시 type 코드: `LegacyTypeCode::kUnderweight(100)` … `kObesity(400)` — 단일 정의만
    - 물리/통계: `PhysicalUnits::`, `StatisticsScale::`, `BmiCategoryMeta::`
    - CSV 컬럼: `CsvReader::Column` enum 사용
    - 신규 API는 `BmiCategory` enum 우선; `getBmiRatio(typeCode)`는 하위 호환용

[T] 아래 요구를 만족하는 `.cursorrules` 내용을 작성해줘.

    ### 절대 규칙 (동작 변경 금지)
    - BMI 분류 경계: 18.5, 23, 25 — **BMI=25.0은 반드시 Obesity**
    - 0으로 나누기 금지 (height=0, 빈 연령대, sum=0 등 방어 유지)
    - `HealthRecord` 필드 의미 유지: id, age, weightKg, heightCm, bmi
    - `processFile` 성공 시 건수 반환, 실패 시 -1 반환
    - 레거시 API 하위 호환: `getBmiRatio`, `SHealth::kType100~400`, `computeBmi`/`classifyBmi` static
    - `categoryFromTypeCode` invalid code → `std::nullopt`; `getBmiRatio` invalid → 0.0

    ### 아키텍처 규칙
    - SRP 유지: I/O·파싱·보정·계산·통계·파사드 역할 혼합 금지
    - God Class 재발 금지 — 새 로직은 적절한 클래스에 추가, `SHealth`는 조율만
    - 매직 넘버 금지 — 기존 namespace 상수 재사용 또는 동일 패턴으로 추가
    - `DataImputer` 보정 로직은 `imputeFieldByAgeDecade` 단일 구현 유지 (체중/키 중복 구현 금지)
    - `BmiStatistics::compute` 단일 패스 집계 유지 (불필요한 다중 full scan 금지)

    ### 테스트 규칙
    - Google Test: `TEST(SHealthBmiTest, ...)` 형식
    - 리팩토링·기능 변경 전후 **ctest Green** 필수
    - 경계값 TC 필수 포함: BMI 18.5, 23, 25 / height=0, weight=0 보정
    - CSV 테스트는 임시 파일 또는 인메모리 문자열 사용
    - 테스트 추가·수정 시 기존 10건 TC 회귀 없어야 함
    - Given-When-Then 구조를 주석 또는 테스트명으로 명시

    ### 코딩 스타일
    - C++17: `enum class`, `constexpr`, `std::optional`, `std::vector`, `std::array` 우선
    - 헤더: `#pragma once`, 구현 분리 (.h / .cpp)
    - 네이밍: PascalCase(클래스), camelCase(함수/변수), kPrefix(상수)
    - CMakeLists.txt 수정 시 `shealth_lib`에 새 .cpp 추가, include path `src/main/cpp` 유지
    - build/ 디렉터리·googletest 캐시는 수정/커밋 대상 아님

    ### 리팩토링 규칙
    - 테스트 Green 상태에서만 리팩토링 진행
    - 1차: 네이밍·상수화·함수 추출·중복 제거
    - 2차: SRP 분리·기능 추가 (전체 비율, 정상 BMI ID, height 보정 등)
    - 3차: 잔여 스멜(type 코드 이중 정의, DataImputer 중복, categoryFromTypeCode 오류 처리) 제거
    - 변경 범위 최소화 — 요청과 무관한 파일 수정 금지
    - API 변경 시 기존 public API alias/위임으로 하위 호환 유지

    ### AI 작업 시 금지·주의
    - BMI 분류 if-else를 여러 파일에 분산 정의하지 말 것 (`BmiCalculator::classify` 단일 진실 원천)
    - `categoryFromTypeCode` default를 임의 카테고리로 반환하지 말 것
    - 고정 크기 C 배열·24개 ratio 멤버 등 레거시 패턴 재도입 금지
    - README·Report/*.md는 사용자 요청 없이 수정하지 말 것
    - git commit/push는 사용자 명시 요청 시에만

    ### 참고 문서 (규칙 작성 시 반영)
    - README.md: 도메인 요구사항·빌드 방법
    - Report/1~3차_Refactoring_보고서.md: 누적 설계 결정·해결된 버그·잔여 과제

[F] `.cursorrules` 파일에 그대로 붙여넣을 수 있는 텍스트.
    - Markdown 또는 plain text
    - 섹션: Project Context / Domain Rules / Architecture / Testing / Coding Style /
      Refactoring Workflow / Do Not / Build Commands
    - 한국어와 영어 혼용 가능 (코드·API명은 영어, 설명은 한국어)
    - 불필요한 서론·요약 없이 규칙 본문만 출력
```
