```
@README.md
@src/main/cpp/
@src/test/cpp/

[P] 시니어 C++ QA 엔지니어 관점에서
    도메인 경계값(BMI 구간, 연령대, 결측치 보정)과 테스트 설계에 엄격합니다.

[C] SHealth BMI C++17 프로젝트 (CMake, Google Test)
    - 입력: CSV `id,age,weight,height` (예: shealth.dat)
    - BMI: weight(kg) / (height(m))²
    - 분류: ≤18.5 저체중, 18.5초과~23미만 정상, 23이상~25미만 과체중, 25이상 비만
    - 결측 보정: weight=0 또는 height=0 → 동일 연령대(10년 단위) 평균으로 대체
    - 연령대: 20~70세, 10년 단위 (20대, 30대, …)
    - README 후속 활동: 코드 스멜 분석 → 1차 리팩토링 → Unit Test → 기능 개선(SRP·연령대 분포·height 보정·정상 BMI 사용자 목록·전체 비율)
    - 구현 참고(있을 경우): SHealth, BmiCalculator, DataImputer, BmiStatistics, CsvReader, BmiTypes

[T] README와 현재 코드(있으면)를 함께 읽고, 요구사항을 C++ 구현·테스트 관점에서 재정리해줘.

    1) 도메인·데이터 모델 표
       - HealthRecord 필드(id, age, weightKg, heightCm, bmi) 의미·단위
       - CSV 파싱 규칙(헤더, 구분자, 컬럼 순서, 빈 줄·잘못된 행 처리)

    2) BMI 계산·분류 비즈니스 규칙 표
       - compute 공식, height≤0 / bmi≤0 처리
       - BmiCategory 4종별 조건식 (18.5, 23, 25 경계 — ≤ vs < 명시, BMI=25.0 포함 여부)
       - LegacyTypeCode(100/200/300/400) ↔ BmiCategory 매핑

    3) 연령대(Age Decade) 규칙 표
       - 20~70세, 10년 단위 구간 정의 (20대=20~29 등)
       - 20대 미만·70대 초과 사용자 통계 포함 여부
       - 연령대별 집계 vs 전체(overall) 집계 차이

    4) 결측치 보정(Imputation) 명세
       - weight=0, height=0 각각의 보정 순서·평균 산출 대상
       - 동 연령대에 유효값이 없을 때 동작
       - 보정 → BMI 재계산 파이프라인 순서

    5) 통계·조회 API 요구사항 표
       - processFile 반환값(성공 건수 / 실패 -1)
       - getCategoryRatio / getBmiRatio / getDecadeDistribution / getOverallDistribution
       - getOverallCategoryRatio / getNormalBmiUserIds
       - 비율 단위(0~100%), 분모 0·무효 BMI 제외 시 반환값

    6) C++ 구현 시 주의점
       - 부동소수 비교(EXPECT_NEAR 허용 오차, 경계값 18.5/23/25)
       - 0으로 나누기 방어(height=0, 빈 연령대, validCount=0)
       - CSV 파싱(stoi/stod 예외, tokens.size() 검증, empty line continue)
       - enum class / std::optional / constexpr 상수 사용 시 테스트 영향

    7) README “기능 개선” 항목 명세 (요구사항 ID 부여)
       - 연령대 BMI 분포 비율
       - height=0 평균 보정
       - 정상 BMI 사용자 ID 목록
       - 전체 대비 범주별 비율
       (각 항목: 입력 / 출력 / 전제조건 / 예외)

    8) Google Test 기준 테스트 시나리오 목록 (번호)
       - BMI 계산·분류 경계값(18.5, 23, 25)
       - weight/height 결측 보정
       - 연령대·전체 통계 일관성
       - CSV/파일 오류·잘못된 행 skip
       - README 기능 개선 항목 대응 TC
       - 레거시 type code·invalid type code

    README 명세와 코드 구현이 다르면 표에 “명세 vs 구현” 열을 두고 차이를 명시할 것.

[F] Markdown (표 + 번호 목록). docs 폴더 안에 requirements_analysis.md로 저장
```
