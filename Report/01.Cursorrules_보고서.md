## 1. 개요

본 보고서는 **3차 리팩토링 완료** 이후, 1~3차 누적 설계 결정·도메인 규칙·테스트 기준을 **Cursor AI가 일관되게 따를 수 있도록** 프로젝트 루트에 `.cursorrules` 파일을 작성한 작업을 정리한 문서입니다.

1~3차에서 코드 품질과 아키텍처는 정리되었으나, AI 보조 개발 시 다음 문제가 반복될 수 있었습니다.

| 문제 | 설명 |
|------|------|
| **도메인 회귀** | BMI 경계값(18.5, 23, 25) 또는 `BMI=25.0 → Obesity` 규칙이 변경될 위험 |
| **아키텍처 훼손** | God Class 재발, `DataImputer`/`BmiStatistics` 중복 로직 재도입 |
| **3차 설계 역행** | `categoryFromTypeCode` invalid 처리, `LegacyTypeCode` 이중 정의 재발 |
| **테스트 무시** | 리팩토링 전 `ctest` Green 미확인, 10건 TC 회귀 |
| **지식 분산** | README·1~3차 보고서·코드에 흩어진 규칙을 AI가 매 세션 재학습 |

4차에서는 **코드 변경 없이** 위 지식을 **단일 거버넌스 문서**로 통합했습니다.

## 4. 핵심 규칙 요약

### 4.1 절대 규칙 (동작 변경 금지)

```
BMI 분류 (BmiThresholds + BmiCalculator::classify 단일 정의)
  ≤ 18.5        → Underweight
  18.5 초과~23 미만 → Normal
  23 이상~25 미만   → Overweight
  ≥ 25 (25.0 포함) → Obesity   ← 반드시 비만

결측: weight=0 또는 height=0 → 동일 연령대 평균 대체
제외: height≤0 또는 bmi≤0 → 통계 집계 제외, 0으로 나누기 금지
processFile: 성공=건수, 실패=-1
invalid type code: categoryFromTypeCode → nullopt, getBmiRatio → 0.0
```

### 4.2 아키텍처 가드레일

| 모듈 | AI가 지켜야 할 제약 |
|------|---------------------|
| `SHealth` | 조율(파사드)만 — God Class 재발 금지 |
| `BmiCalculator` | BMI 분류 **단일 진실 원천** |
| `DataImputer` | `imputeFieldByAgeDecade` 단일 구현 |
| `BmiStatistics` | `compute` 단일 패스 집계 |
| `BmiTypes` | `LegacyTypeCode`, `BmiThresholds` 등 **단일 정의** |
| `CsvReader` | `Column` enum 사용 |

### 4.3 테스트 게이트

- 리팩토링·기능 변경 **전후 `ctest --output-on-failure` Green**
- 회귀 기준 **10건 TC** (3차 완료 시점과 동일)
- 신규·수정 TC에 경계값 **18.5, 23, 25** 및 **weight/height=0 보정** 포함

## 9. 회고 (4차)

### 9.1 달성

- 1~3차에서 축적한 **설계 결정을 AI가 재현 가능한 형태**로 고정했다.
- 특히 3차에서 수정한 **Major 스멜 3건**(DataImputer 중복, type code 이중 정의, invalid type 오분류)의 **재발 방지 규칙**을 명시했다.
- 코드 변경 없이 **지식 전달 비용**을 줄였다.

### 9.2 설계 원칙

- **규칙은 코드와 동기화**: namespace·API·TC 이름을 실제 코드에서 인용
- **절대 규칙 vs 가이드 분리**: Domain Rules / Do Not에 회귀 방지 항목 집중
- **최소 침습**: README·Report는 사용자 요청 없이 AI가 수정하지 않도록 Do Not에 명시

### 9.3 한계·향후

| 항목 | 설명 |
|------|------|
| `.cursorrules` vs `.cursor/rules/` | Cursor 버전에 따라 Rules UI·경로가 다를 수 있음 — 필요 시 `.cursor/rules/*.mdc`로 분할 이전 검토 |
| 규칙 drift | 코드 변경 시 `.cursorrules` 수동 동기화 필요 — API·TC 추가 시 규칙 업데이트 권장 |
| 실데이터 TC | `shealth.dat` 기반 통합 테스트는 여전히 미구현 |
| Prompting 폴더 | `Prompting/Refactoring-Prompt.md`는 분석용 이력 — `.cursorrules`와 역할 구분 유지 |
