## 1. 개요

본 보고서는 **3차 리팩토링·4차 `.cursorrules` 정립** 이후, README 실습 목표와 `src/main/cpp`, `src/test/cpp` 구현을 **시니어 C++ QA 관점**에서 대조·문서화한 **5차 활동(요구사항 분석)** 결과를 정리합니다.

1~4차까지 코드 구조·도메인 규칙·AI 협업 가이드는 정리되었으나, 다음 공백이 남아 있었습니다.

| 공백 | 설명 |
|------|------|
| **명세 분산** | BMI 경계(≤ vs <), 연령대 포함 범위, 결측 정의가 README·코드·보고서에 분산 |
| **명세 vs 구현** | README는 체중 0 보정만 언급, 구현은 키 0 보정·FI 기능까지 확장 |
| **테스트 갭** | 기존 10건 TC와 미검증 엣지(연령 경계, 파일 실패, `bmi≤0` 집계)의 대응 관계 불명확 |
| **회귀 기준** | `shealth.dat` 통합 TC·추가 경계 TC 필요 여부를 문서로 고정하지 않음 |

5차에서는 **코드 변경 없이** 위 내용을 단일 요구사항 문서로 통합하고, Report에 **요약·리스크·후속 과제**를 기록했습니다.

## 4. 처리 파이프라인 (확정 계약)

현재 구현의 **고정 처리 순서**는 다음과 같습니다. 요구사항·TC 설계 시 이 순서를 전제로 합니다.

```
CSV 파일
  → CsvReader::load          (HealthRecord, bmi=0)
  → DataImputer::impute      (weight 0 → height 0 순)
  → BmiCalculator::applyToAll
  → BmiStatistics::compute
  → SHealth API 조회
```

`SHealth::processFile` 성공 시 **유효 로드 건수**, 파일 열기 실패 시 **-1** 반환.

## 5. 핵심 도메인 규칙 요약

### 5.1 BMI 분류 (단일 SoT: `BmiCalculator::classify`)

| 범주 | 조건 | 경계 메모 |
|------|------|-----------|
| Underweight | BMI **≤ 18.5** | 18.5 → 저체중 |
| Normal | **18.5 <** BMI **< 23** | 23.0 → 정상 아님 |
| Overweight | **23 ≤** BMI **< 25** | 23.0 → 과체중 |
| Obesity | BMI **≥ 25** | **25.0 → 비만** (1차 버그 수정 유지) |

**QA 주의**: `bmi ≤ 0`은 `classify`상 Underweight이나, **`BmiStatistics`에서는 전부 제외** — 분류 API와 집계 API를 혼동하지 않을 것.

### 5.2 결측 보정 (`DataImputer`)

| 항목 | 규칙 |
|------|------|
| 결측 표현 | `weightKg == 0.0` 또는 `heightCm == 0.0` (정확히 0, epsilon 아님) |
| 보정 순서 | 체중 → 키 (`imputeFieldByAgeDecade` 동일 알고리즘) |
| 평균 대상 | 동 연령대(`AgeDecade::contains`) 내 **비결측** 값만 |
| 실패 | 동 대 `validCount == 0` → 해당 필드 미보정 |

### 5.3 연령대

| 라벨 | 포함 나이 |
|------|-----------|
| 20대 | 20 ≤ age < 30 |
| … | 10년 단위 |
| 70대 | **70 ≤ age < 80** (71~79세 포함) |

| 사용자 | 연령대 집계 | 전체 집계 |
|--------|-------------|-----------|
| age < 20 | 제외 | 유효 BMI면 포함 |
| age ≥ 80 | 제외 | 유효 BMI면 포함 |

### 5.4 레거시 type code

| Code | BmiCategory |
|------|-------------|
| 100 | Underweight |
| 200 | Normal |
| 300 | Overweight |
| 400 | Obesity |
| 기타 | `std::nullopt` → `getBmiRatio` = **0.0** |

## 6. README 기능 개선(FI) 대응 현황

| ID | README 항목 | 구현 API | TC |
|----|-------------|----------|-----|
| **FI-01** | 연령대 BMI 분포 비율 | `getDecadeDistribution`, `getCategoryRatio` | `DecadeDistributionMatchesCategoryRatio` |
| **FI-02** | height=0 평균 보정 | `DataImputer` (height 필드) | `ImputeMissingHeightByDecade` |
| **FI-03** | 정상 BMI 사용자 ID | `getNormalBmiUserIds` | `NormalBmiUserIds` |
| **FI-04** | 전체 범주별 비율 | `getOverallDistribution`, `getOverallCategoryRatio` | `OverallCategoryRatio` |

**SRP 분리**(CsvReader / BmiCalculator / DataImputer / BmiStatistics / SHealth 파사드)는 2~3차에서 완료, 본 분석에서 **요구사항 충족**으로 판정.

## 13. 회고 (5차)

### 13.1 달성

- README·코드·테스트를 **한 문서(`docs/requirements_analysis.md`)**에 정렬해, 이후 TC·리팩토링의 **판단 기준**을 마련했다.
- **명세 vs 구현** 갭 6건을 식별·우선순위화했다.
- FI-01~04와 10건 TC의 **추적 가능성**(요구사항 ID ↔ API ↔ 테스트명)을 확보했다.

### 13.2 설계·QA 원칙

- **경계값은 수학 기호로 먼저, 코드는 그 다음** — 18.5/23/25 off-by-one 방지
- **파이프라인 순서 고정** — 보정 후 BMI, 집계는 유효 BMI만
- **레거시와 권장 API 병기** — `getBmiRatio` vs `getCategoryRatio` 문서화

### 13.3 한계

- **동적 검증 없음** — 본 단계는 정적 분석·문서화만 수행 (`ctest` 재실행은 후속)
- **Prompting 폴더** — 분석 프롬프트 이력과 `docs/` SoT 역할 구분 필요
- **다국어** — 본문은 한국어; 코드 식별자는 영문 유지
