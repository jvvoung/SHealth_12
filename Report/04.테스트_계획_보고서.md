## 1. 개요

본 보고서는 **3차 리팩토링·요구사항 분석** 이후, **단위 테스트 보강**을 전담하는 `tc` 브랜치에서 수행한 **6차 활동(테스트 계획)** 결과를 정리합니다.

요구사항 분석(5차) 단계에서 `docs/requirements_analysis.md`로 도메인·API·기존 10건 TC의 갭이 식별되었으나, 다음 항목은 아직 문서·브랜치·실행 기준으로 고정되지 않았습니다.

| 공백 | 설명 |
|------|------|
| **우선순위 부재** | P0/P1/P2 없이 “추가 TC 12건”만 나열 → 스프린트·PR 게이트 불명확 |
| **모듈별 책임** | `BmiCalculator` 등 모듈 단위 vs `SHealth` 통합 테스트 범위 미정 |
| **경계값 매트릭스** | BMI·연령·결측·비율 시나리오와 기존 TC 매핑 표 부재 |
| **커버리지** | gcov/lcov 미설정, 목표치·측정 방법 없음 |
| **브랜치 전략** | 리팩토링 완료선(`Refactoring`)과 TC 작업 분리 미정 |

6차에서는 **코드 변경 없이** 시니어 QA 관점 테스트 계획서를 작성하고, `tc` 브랜치·README·Report 체계를 정비했습니다.

## 4. 테스트 전략 요약

### 4.1 파이프라인 (검증 대상)

```
CsvReader::load
    → DataImputer::imputeMissingValues   (weight → height)
    → BmiCalculator::applyToAll
    → BmiStatistics::compute
         ↑ SHealth::processFile 고정 순서
```

**QA 핵심 불변식** (TC 설계 시 반드시 검증)

1. 결측: `weightKg == 0.0` / `heightCm == 0.0` (`==` 비교, epsilon 아님)
2. `heightCm ≤ 0` → `bmi = 0` (`PhysicalUnits::kInvalidBmi`)
3. `bmi ≤ 0` → **통계·정상 ID 목록 제외** (분류는 Underweight 가능 — R1 리스크)
4. 연령대 집계: `AgeDecade::contains` + `indexForDecade` 유효 시만
5. 전체 집계: 유효 BMI 전 레코드 (age 19·80+ 포함 가능)

### 4.2 모듈별 테스트 책임

| 모듈 | 핵심 검증 | 직접 단위 TC | 통합 TC |
|------|-----------|--------------|---------|
| `BmiCalculator` | 공식, 4분류 경계, height≤0 | 권장 | ✅ 기존 |
| `DataImputer` | 연령대 평균, validCount==0 | 권장 | ✅ 기존 |
| `CsvReader` | skip, 파일 실패 | 권장 | 일부 |
| `BmiStatistics` | 비율 %, 분모 0, ID 목록 | 권장 | ✅ 기존 |
| `BmiTypes` | `categoryFromTypeCode`, `AgeDecade` | 권장 | 부분 |
| `SHealth` | `processFile`, 파사드 API | 통합 중심 | ✅ |

### 4.3 우선순위 정의

| 등급 | 의미 | 게이트 |
|------|------|--------|
| **P0** | 도메인 정확성·크래시 방지·파이프라인 불변식 | **Green 필수**, PR 차단 |
| **P1** | 경계·엣지·회귀 방지 | 1차 스프린트 내 권장 |
| **P2** | 골든 데이터·CLI·커버리지 90%+ | 선택·CI 강화 |

## 13. 회고 (6차)

### 13.1 달성

- 요구사항 분석의 **“권장 TC 12건”**을 **27개 시나리오·P0/P1/P2·모듈 매핑**으로 구체화했다.
- `tc` 브랜치로 **리팩토링 완료선과 TC 작업을 분리**해, 회귀 범위를 명확히 했다.
- **커버리지 목표·측정 경로**(GCC/MSVC)를 문서화해, “몇 %까지 올릴지” 기준을 마련했다.
- 기존 10건 TC를 **요구사항 ID·갭 표**와 연결해 추적 가능성을 유지했다.

### 13.2 설계·QA 원칙

- **계획과 구현 분리** — 6차는 SoT 문서만, 구현은 Phase A부터
- **P0는 실패 경로·불변식** — happy path만으로는 R1·R5 잔존
- **통합 우선, 모듈 분리는 P2** — 현 구조에서 `SHealth` 파이프라인 TC가 ROI 최대

### 13.3 한계

- **실제 TC 추가·ctest 실행 결과 없음** — 본 단계는 계획만 완료
- **`docs/test_plan.md` 미커밋** — 로컬 작성 후 Report와 함께 커밋 권장
- **README vs Report 번호** — 02/03/04 체계 혼재 가능, 링크만 상호 참조로 완화
