## 1. 개요

본 보고서는 **7차(TC 구현)** 이후 수행한 **8차 활동(결함 분석·QA 검증)** 결과를 정리합니다.

7차에서 `SHealthBMITest.cpp`가 10건→36건으로 확장되었고, 1차 ctest 실행 시 **1건 실패**(`BmiStatisticsTest.SingleRecord_OverallHundredPercent`)가 확인되었습니다. 픽스처 수정 후 전체 Green을 달성했으며, 본 차수에서는 **파이프라인 단위 추적**, **명세 대조**, **잔존 리스크**를 문서화합니다.

| 프로덕션 결함 | 미확정 | **활성 결함 0건** |

## 7. 수정 방안

### 7.1 권고 사항

| 대상 | 조치 | 상태 |
|------|------|------|
| **프로덕션** | 수정 불필요 | ✅ |
| **TC-22 테스트** | 픽스처 `45kg/170cm` + 주석 정정 | ✅ 반영됨 |

### 7.2 이력 diff (테스트만, 참고)

```diff
--- a/src/test/cpp/SHealthBMITest.cpp
+++ b/src/test/cpp/SHealthBMITest.cpp
@@ SingleRecord_OverallHundredPercent
-    records_ = {{1, 25, 50.0, 160.0, 0.0}};
+    records_ = {{1, 25, 45.0, 170.0, 0.0}};
```

**TC 수정 근거**

- TC-22 목적: 단일 유효 레코드 → 한 범주 100%, 4분류 합 100%.
- assert 카테고리는 **픽스처에서 계산 가능한 BMI 분류**와 일치해야 함.
- `50/160` → Normal이므로 Underweight assert는 명세 위반이 아닌 **테스트 오류**.

### 7.3 대안 (범주 무관 검증, 선택)

```cpp
const auto dist = statistics_.getOverallDistribution();
double sum = 0.0;
int nonzero = 0;
for (double r : dist) {
    sum += r;
    if (r > 0.0) ++nonzero;
}
EXPECT_NEAR(sum, 100.0, 0.01);
EXPECT_EQ(nonzero, 1);
```

## 11. 회고 (8차)

### 11.1 달성

- 7차 확장 스위트(36건)에 대해 **파이프라인 단위 QA 분석**을 완료했다.
- 유일 실패는 **프로덕션 결함이 아닌 TC-22 테스트 데이터 오류**로 확정했다.
- 프로덕션 모듈 5종이 README·`requirements_analysis.md` 불변식과 **일치**함을 확인했다.

### 11.2 교훈

- **단일 레코드 TC**는 “합 100%”만으로는 부족하고, **기대 범주와 BMI 산출값**을 표로 맞출 것.
- Given-When-Then 주석의 범주 표기는 **계산 검증 후** 작성할 것 (`50/160` → Normal 사례).

### 11.3 한계

- 실패 로그 원문(1차 `EXPECT_NEAR` diff)은 보고서 작성 시점에 보존되지 않음 — 수치는 파이프라인 재계산으로 복원.
- P2 골든·커버리지·CLI는 본 차수 범위 외.
